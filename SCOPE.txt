THREAT MODEL
------------
Angreifer-Faehigkeiten:
  - Netzwerk-MITM (Tor schuetzt Metadaten)
  - Kompromittierter Website-Server (sieht nur verschluesselte Blobs)
  - Phone-Theft (Hardware-Keystore + Argon2 PIN)
  - SaveCard-Besitz (QR1+QR2 reichen fuer Killswitch - by design)
  - Boesartiger Nostr-Relay-Betreiber (sieht nur signed+encrypted Blobs)

WAS BESONDERS GEPRUEFT WERDEN SOLL
-----------------------------------
A. Hardcoded Secrets / Supply-Chain
   - trufflehog-aehnlicher Scan ueber alle Files
   - SRI-Hashes fuer vendor/*.js vorhanden?
   - package-lock Dependencies im oracle/

B. Client-Side Krypto (website/hermes.js + savecard/savetrigger)
   - AES-GCM: IV-Reuse? IV-Entropie ok?
   - Key-Derivation (SHA-256 ohne Salt - bewusst wegen App-Kompat)
   - BIP-340 Schnorr-Signatur Flow korrekt?
   - Nonce/Timestamp im Kill-Event - Replay-Schutz?
   - sessionStorage/localStorage Scope ok?
   - innerHTML / eval / Function Constructor / atob/btoa - XSS?

C. App-Side (Kotlin)
   - KillCommandListener: Signatur-Verifikation vor Verarbeitung?
   - canonical event.id check?
   - target == myNostrPubkey enforce?
   - Replay-Protection persistiert ueber Restart?
   - Bip340Verifier mathematisch korrekt?
   - Exported Components im AndroidManifest ohne Permission?
   - WebView mit JavaScriptInterface?

D. Server (oracle/relay_publish_server.js)
   - Input-Validation fuer /relay-publish?
   - Nostr-Event Signature-Verification?
   - Kind-Whitelist?
   - Rate-Limiting (echte Client-IP via X-Forwarded-For)?
   - Event-Dedup persistent?
   - CORS Allowlist strikt?
   - Body-Size Cap?

E. Operational / Privacy
   - nginx CSP strict (ohne unsafe-inline/eval)?
   - Permissions-Policy, X-Frame-Options, Referrer-Policy, COOP/CORP?
   - Token-in-URL vs. Token-in-Hash (Browser-History/Logs/Referer-Leak)?
   - Oracle Server haertung: Keine 0.0.0.0 bindings? SSH ueber Tor?
